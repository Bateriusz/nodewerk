# NW-12A: Neon Breach / Room 07

An original 48-second procedural 3D science-fiction demo from issue [#46](https://github.com/Bateriusz/nodewerk/issues/46), built on merged nodewerk main
`1c9e1559c8d43530c7b213461c6719b6aa43ae35` (tree `4b73007a5321e9c8ad89eac70de2f0219a542080`).

The main film renders at **1920 x 1080** using real instanced geometry, a moving
perspective camera, depth testing, lighting, bloom and tonemapping. Its visual
language is built from rings: an orbital mothership, ribbed hotel architecture
and articulated mechanical characters. Cyan identifies Barbarella, rose the
guards and amber the agent who escapes. Barbarella teleports to the hotel,
breaches the security door and fires a stylized beam. One agent escapes through
a service hatch on his own, then incapacitates her from the corridor with a
fictional disruptor. The finale uses four original lines. Geometry, choreography,
shaders, glyphs and the development score are original procedural work.

This revision uses the existing **common D3D12 rasterization path**. It does not
enable or claim hardware ray tracing. It adds production content without
extending the engine, operator vocabulary or package/runtime interfaces.

## Download and run

The core workflow's existing pinned Windows build job produces the four
specialized players and their embedded packages with `tools/audio_demo.py`.
The latest Windows 11 runtime job verifies the transfer SHA manifest, launches
the exact shipped bytes at fixed ticks under WARP without a window or endpoint,
then uploads **nodewerk-nw12a-demo-windows** for the PR. Use the artifact from the
successful PR run, not an earlier build. The zip contains EXEs, the menu,
short README, cue table and checksums; it is not a source or toolchain bundle.

On Windows 11 x64, extract the full directory. Double-click
`PLAY-NEON-BREACH.cmd` (or `neon-breach.exe` for the continuous story). The menu
offers the three optional in-universe mission archives; it starts the main film
automatically after five seconds. Quit with Alt+F4. Relaunch starts at tick zero.
The story requires the common D3D12 profile and an active WASAPI render endpoint.
No codec SDK, separate recording, or network is needed. The archive views are
silent.

The separate **nodewerk-nw12a-demo-preview** artifact is generated by the Windows
CI preview step. Its native captures use a diagnostic player built around the
same embedded scene package; this companion executable is distinct from the
shipped player. Use the preview from the same source revision as the runnable
artifact. Capture generation is not a physical display or audio-device check.

## 3D content on the existing renderer

`fixtures/nw12a/neon_breach.nwgraph` reaches the existing 14-node procedural
geometry/material/camera/post chain. It generates a 48-by-12-segment torus and
1,024 instances. Production shaders place and animate those rings as architecture,
characters, doors, props and effects in shared world space. The normal instanced
draw and depth buffer provide perspective, occlusion and parallax.

`tools/audio_demo.py` follows the established Orbital Vortex content-specialization
mechanism: it supplies local authored content for existing fixed shader slots
2, 6, 7 and 9 during export, then restores the shared shader definitions. These
are the instance, vertex, material-lighting pixel and final tonemap/overlay
stages of the existing pipeline. All other geometry generation, scheduling,
draw, depth, bloom, package and player behavior comes from the shared backend.

The graph authors the existing operator chain and its supported parameters;
the production shaders author the individual ring constructions, character
poses and shot choreography. This is not a general scene-composition or camera-cut
operator system. Those missing reusable authoring capabilities, together with
material-aware scene reflections and spatial History effects, are recorded in
[NW-13 (#36)](https://github.com/Bateriusz/nodewerk/issues/36).

The main film's sparks and debris are animated geometry instances. The current
History exporter does not compose its image outputs into this 3D render, so the
actual NW-09 particle and feedback operators remain in separate optional archive
players. Those archives retain their real stateful execution; they are not
claimed as effects inside the main film. NW-11's optional mesh/ray-query
experiments likewise require broader content integration before they can serve
this production and are not enabled here.

## One clock, separate song and motion

The actual NW-12 `AUDI`/`NWAS` capability is on the main generated player:
WASAPI's absolute 48 kHz clock supplies the render tick and its own fixed-point
procedural synthesis produces every note and transient. A single JSON cue
table generates the shader cue constants and synthesizer event ticks. Representative
events are committed on exact 60 fps frame boundaries (800 samples). At each
cue the headless smoke checks that the rendered timing marker is off on the prior
frame and on at the boundary; the same cue constants drive the corresponding
flash, beam, hit or door event. The marker check establishes cue scheduling, not
the visual readability of the action. The portable test executes the real NW-12
offline PCM writer twice (music alone and effects mix) and confirms sample
onsets and matching frame plan for every event.

| Cue | Tick / first PCM sample | 60 fps frame |
| --- | ---: | ---: |
| Teleport | 384000 | 480 |
| Door impact | 720000 | 900 |
| First shot | 1008000 | 1260 |
| First impact | 1032000 | 1290 |
| Second shot | 1401600 | 1752 |
| Second impact | 1425600 | 1782 |
| Agent slips out | 1512000 | 1890 |
| Hatch seals / agent outside | 1872000 | 2340 |
| Agent fires the fictional disruptor | 1920000 | 2400 |
| Barbarella is incapacitated | 1944000 | 2430 |
| Original end card | 2064000 | 2580 |

The presentation clock does not move backwards. The authored action time is
reconstructed by a continuous piecewise integer map: forward at 1×, quarter
speed from 22–25 s, frozen from 25–27 s, reversing at half speed from 27–29 s,
then forward at 1×. Character and action transforms are derived from this mapped
time. The camera uses presentation time, so it can move around the frozen action;
the HUD and absolute audio score also continue forward. Audio effects occur once
at their authored sample positions and are not retriggered by visual reverse.
This reconstructs authored motion rather than reversing a physical simulation.
The independent History chapters play forward only and do not claim native
backward History seek.

The bundled score (`fixtures/nw12a/development-score.json`) is the original
development accompaniment, not an arrangement, transcription or recording of
Clutch's *In Walks Barbarella*. Approved note data can replace the music part
without modifying the visuals/effects. Supply an authorized local note-event
JSON **at build time**, not an audio file:

```text
python tools/audio_demo.py build --player-template <configured-Windows-EXE> --dxc <pinned-DXC> --score <authorized-score.json> --output <new-dir>
```

Use fields `version: 1`, `title`, `kind: "authorized_arrangement"`,
`duration_ticks: 2304000`, and `notes` (rows of absolute start tick, duration
ticks, frequency in millihertz, positive gain up to 32767). Note and cue effects
together must fit the native NWAS 64-event bound; remix the authorized excerpt
within that bound rather than silently truncating it. Regenerate cue positions
only when permitted musical timing data is available. Invalid, absent explicitly
requested, or recording inputs fail closed; the default build uses only the
original repository score. No actual Clutch notes, recording or beats have
been verified for this demo. Do not redistribute a replacement without the
appropriate rights. The four display lines are read at build time from
`fixtures/nw12a/finale.txt`. Use `--finale-text <file>` to substitute four
original/authorized uppercase lines (up to 46 characters in the built-in font).
The requested lyrics are not bundled or reproduced; changing the text does
not modify the procedural audio or cue timings.

## Evidence limits

The actual offline PCM test uses a native synth executable. Portable package
contract tests use test DXIL, not a claim of compiled Windows visuals. Hosted
Windows smoke checks the actual staged players headlessly. Native preview frames
provide inspectable scene output from the same embedded package; the diagnostic
player is not a byte-identical copy of the shipped executable. Neither path
establishes physical Windows playback/alignment or GPU timing. Record those
observations separately on the target desktop. The current build also does not
establish use of the intended song; its original development score remains explicit.
