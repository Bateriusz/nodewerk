## Result

The proof scene is expressed only as typed graph operators and compact
procedural parameters:

- `nw.texture.noise2d` with an explicit `seed`, 256x256 dimensions, four
  seeded value-noise octaves, and an R8G8B8A8_UNORM target;
- `nw.mesh.torus` with 64 major and 32 minor segments, producing 2,048
  vertices and 12,288 indices;
- `nw.scene.instances` with 256 procedurally placed records and a dense
  one-record material table;
- `nw.material.standard`, `nw.camera.curve`, `nw.animation.twist`,
  `nw.render.instanced`, `nw.post.bloom`, `nw.post.tonemap`, and the existing
  `nw.render.present` terminal.

The baseline package carries only explicit seeds, sizes, radii, curve keys,
material values, and shader payloads. It does **not** contain a baked texture,
vertex buffer, index buffer, instance table, or material table. The texture and
mesh buffers are generated by GPU initialization dispatches, and no frame
instruction performs CPU content readback.

The render path is a single conventional indexed instanced indirect draw. The
vertex stage reads a dense flat instance table and applies analytic twist
deformation and an absolute-tick camera curve. The pixel stage performs
analytic directional lighting and samples the seeded Noise2D material. A
half-resolution bloom pass and a tonemap pass produce the existing
`frame.present` RGBA32F UAV buffer.

## Initialization and frame partitioning

The optimizer places the texture recipe, torus recipe, instance recipe, and
their explicit residency-generation nodes in `initialization`. Their
`init.create_resource`, generation pipeline, descriptor-table, and
`init.dispatch` instructions execute exactly once at startup. The static
generators never appear in `FRAM`.

Generation writes:

- the 256x256 seeded Noise2D texture;
- 2,048 torus vertices and 12,288 uint32 indices;
- 256 dense instance records;
- one 32-byte material record;
- one 20-byte `DRAW_INDEXED_INSTANCED` argument record.

The frame stream is bounded and conventional:

1. absolute tick selection for the camera curve;
2. read-state barriers for generated resources;
3. one graphics root signature, root constants, and descriptor tables;
4. one graphics pipeline selection and render-target bind (colour and depth
   are explicitly cleared);
5. exactly one `frame.execute_indirect` draw;
6. half-resolution bloom dispatch;
7. full-resolution tonemap dispatch;
8. `frame.present` of the final RGBA32F UAV buffer.

The presented post chain is traced from graph input edges rather than preferred
node names. The fixed player supports one half-resolution bloom stage followed
by one tonemap stage; a reordered or duplicate chain fails export explicitly
instead of silently executing a different sequence. The graphics root
signature serializes
`D3D12_ROOT_SIGNATURE_FLAG_ALLOW_INPUT_ASSEMBLER_INPUT_LAYOUT`, matching the
PSO's nonempty vertex input layout.

seed/control outputs may be checked with exact hashes.

## Timeline and stateless evaluation

`tools/nw06_timeline.py` fixes time at **48,000 integer ticks per second**.
Conversions from seconds and monotonic nanoseconds are checked for range and
overflow. Capture frame steps are exact rational values, so no floating-point
delta accumulation can affect a tick.

The camera curve is sampled by absolute tick. The stateless first scene has no
history accumulator: direct `seek(tick)` and evaluation at `tick` produce the
same camera/scene state. Curves validate strictly increasing absolute ticks,
finite values, and declared value ranges. Bounded quantization records the
measured maximum absolute error and fails if it exceeds the declared tolerance.
`full_precision=True` (or `bits=None` with the explicit escape hatch) retains
the original curve exactly.

Events are ordered by increasing `(tick, event_id)` with unique IDs. Delivery is
over `(previousTick, currentTick]`. Calling `advance()` at the same tick delivers
nothing. A backwards advance fails. `seek(tick)` resets the event cursor so the
next advance delivers only events strictly after `tick`; an explicit
`seek(0, replay_from_start=True)` plus `advance()` or `replay_through()`
replays from the beginning. Seeking never mutates timeline or stateless scene
data.

`ClockProvider` is a standard-library-only protocol reserved for later audio
synchronization. No audio library is imported or linked.

Generated NW-06 playback converts elapsed monotonic time to 48 kHz integer
ticks with checked overflow, so display refresh rate cannot change scene speed.
Offline capture uses an exact rational frame index (`frame_index * numerator /
denominator`) from the package timeline. The generated link manifest selects
the NW-06 clock/rational path; unchanged NW-05 exports retain their existing
frame-counter loop.

## Resource and failure behavior

Invalid dimensions, indices, curve ranges, negative/invalid quantization
widths, duplicate event IDs, and budget violations fail before dispatch. The
exporter is transactional: generation or pipeline failures preserve the previous
complete authoring preview, and standalone initialization failure keeps the
previous artifact. Missing capability/device support, invalid shader payloads,
and budget violations fail closed.

Only `cs_6_0`, `vs_6_0`, and `ps_6_0` are emitted. There are no mandatory mesh
shaders, ray-tracing tiers, bindless heap indexing, FP16 arithmetic, enhanced
barriers, wave-size assumptions, or runtime shader compilers.

## Verification

```bash
python tools/verify_nw06.py --mode ContractsOnly --summary-json build/nw06.json
python -m pytest -q tests/test_nw06_*.py
```

`ContractsOnly` validates the procedural CPU/high-precision references, exact
layouts, topology, instance/material tables, timeline/event semantics,
capability requirements, generated link closure, deterministic package and
manifest identity, and evidence schema. Contract-only success does not imply
hardware acceptance.

Hardware evidence remains `pending_unverified` until the identical common
artifact is captured at fixed ticks on representative desktop Ada and Blackwell
hardware. Each capture records coverage target, evidence role, identical
artifact/package/manifest hashes, common profile and requirements digest, exact
adapter/device, driver/OS/toolchain, queried capabilities, clocks/power/thermal
information, cache state, capture protocol, unavailable telemetry, evaluated
fixed ticks, capture artifacts, and validated numeric/image comparisons against
the declared tolerances. A bare `status: passed` or caller-supplied
qualification label is insufficient: missing required telemetry or comparison
evidence stays pending, and an executed failure stays failed. Hardware
classification is metadata only and never changes target selection, tolerances,
quality/resolution requirements, or feature exclusions.

Per-pass time, initialization time, shader bytes, and memory costs use the
existing instrumentation and attribution architecture. Unavailable
measurements are recorded explicitly rather than fabricated.
